# 已知限制与未来计划

## 已知限制

- 离线 fixture 只支持日线 20 / 60 / 120 日演练，不支持 1 分钟或日内混合模式。
- 现有浏览器 E2E 主要验证前端交互和 HTTP 契约，部分 API 使用 mock；统一验证脚本已增加一条无 mock 的日线 Fixture 浏览器闭环，但尚未覆盖分钟与日内混合模式。
- 仓库没有 CI workflow 和覆盖率阈值；分层门禁当前通过本地脚本执行。
- Python 依赖没有完整 lockfile；Node 复现以两个 `package-lock.json` 和 `npm ci` 为准。
- 本次只验证 Python 3.11.15 与 Node 25.5.0，不代表 README 所列全部版本的矩阵验证。
- 在线模式仍依赖通达信服务和本地缓存覆盖；外部节点、退市证券和分钟行情可用性不由本项目控制。
- Demo 视频没有旁白，以页面操作和内嵌字幕讲解；面试时仍建议由作者现场补充取舍与失败处理说明。
- 项目是研究与模拟演练工具，不构成投资建议，也不把历史模拟结果等同于真实收益。

## 下一步优先级

1. 将四层门禁接入 CI，并上传 JUnit、失败截图与 trace；再根据稳定运行结果决定是否设置覆盖率阈值。
2. 为 Python 依赖建立可审查的锁定方案，并验证 README 声明的 Python / Node 支持矩阵。
3. 继续统一行情错误 taxonomy，使日线、分钟和混合模式对缓存不足、外部连接和数据质量使用一致 code。
4. 增加一条移动端关键流程 smoke，并补充键盘与屏幕阅读器检查。

这些计划优先提升可复现性和证据质量，不继续扩展交易策略或收益分析功能。
