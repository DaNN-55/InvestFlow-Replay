# InvestFlow Replay 架构与运行流程地图

直接用浏览器打开同目录的 `index.html`。页面已内嵌数据与展示逻辑，可以离线使用，无需启动 InvestFlow-Replay 服务或安装前端依赖。

## 怎么看

- 初始为模块概览：点击节点看职责与源码定位，点击连线看调用类型和证据。右侧默认展示说明，源码依据按需展开。
- 左侧选择场景，底部逐步演示；失败与重试使用独立分支。「上一步」沿实际访问历史返回。场景列表与主要步骤默认展开，可手动收起；异常分支按需展开，进入分支时自动展开。
- 场景只展示有关模块；返回全局概览恢复完整地图。模块右上角或详情面板可展开内部模块，展开与收起保留原有缩放和位置。
- 切到业务对象，查看创建、关联、读写者与生命周期。
- “待核实”列出代码无法独自证明的运行事项。右上角代码快照显示版本与本次范围。
- 拖动平移、滚轮缩放，或使用画布控制按钮；画布聚焦后方向键平移，`+` / `-` 缩放，`0` 重置。
- 源码位置按项目相对路径、行号和符号显示，可复制定位。行号属于本次快照，后续以符号和实际代码核对。

## 本次场景

1. 新建 A 股盲测：基准状态 → 行情场景 → 冻结会话 → 可见化 → 异步储备；含缓存与上游失败。
2. A 股下单与推进：决策与动作版本 → pending 委托 → bar/按日推进 → 撮合 → 事务写回；含等待、冲突和整日回滚。
3. 盲评、揭晓与复练：完成 → 原始盲评 → 揭晓 → 事后复盘 → 新建复练 → 完成后对照；含独立修正与阶段拒绝。
4. 合约训练与失败恢复：pending 意图 → 冻结资产 → 完整读取 → 预览确认 → 教学执行 → 事务审计 → 读最新版本；含缺资产、读取失败与未知结果重试。
5. 交易追踪与记录来源：同页不同数据源 → 手工计划 → 许可 → 执行事件 → 档案统计；含损坏文件保护。

## 最关键的关系

Web 经 Node API 操作两类训练。A 股创建场景依赖 Python 行情引擎，随后账户撮合在 Node/SQLite 事务中进行；合约训练读取本地冻结历史与规则，在 Node 的纯计算执行器里逐分钟处理。两边都会保存自己的冻结版本和会话状态，不能把合约执行器的 `engine` 误认为 Python 进程。

DuckDB 用于 A 股行情缓存，SQLite 用于两类演练、复盘与审计。手工交易追踪以独立 JSON 保存。共用页面入口不等于共用记录来源，也没有从演练会话自动转换为手工追踪单的实现。

后台工作是 Python 进程内的初始化与维护线程，以及 Node 发起的不等待预取；没有为地图补画队列服务或独立撮合 Worker。合约数据下载与离线导入由独立脚本完成，普通训练不实时向 OKX 下单或请求历史池。

## 数据与更新

- `architecture-data.json`：地图的权威模型、来源、对象与场景。
- `source-snapshot.json`：本次 42 个已引用源文件的 SHA256 与 74 处定位，用于检查更新时的证据是否变动。
- `index.html`：生成的离线页面；修改 JSON 或 `viewer/` 后重新构建，不直接手改 HTML。
- `viewer/`：本项目的 HTML、CSS 与交互脚本。当前为项目内预览版，全局 Skill 模板尚未同步。
- `build_viewer.py`：复用已安装 Skill 的数据校验器，使用本项目的 `viewer/` 生成页面。
- `verification.md`：实际执行的检查、未验证事项与模板修正。
- `checks/`：保留的真实地图断言与示例回归明细。
- `PLAN.md`：本次授权、范围与进度。

从项目根目录重新构建：

```bash
python3 docs/architecture-map/build_viewer.py docs/architecture-map/architecture-data.json --source-root . --output docs/architecture-map/index.html
```

本机已安装全局 `$project-architecture-map`，项目内重复 skill 已移除。需要更新项目事实时，使用全局版本，要求检查代码变化并更新本目录。保留有效 ID 与布局，对照版本与源文件快照重新核实受影响关系，并记录未复查范围。基础架构仍保留 2026-10-24 的快照；2026-10-26 仅更新首页入口相关说明、展示和文案，没有全面复核此后业务变化。其他机器需先安装该 skill，已有 `index.html` 可独立打开。
