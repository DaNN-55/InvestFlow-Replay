# A股板块规则修正：实现与验收

日期：2026-10-19。分支：`codex/replay-order-execution`。已实现并验证，未提交、未推送。

## 成功条件与结果

| 可检查结果 | 实现与证据 |
| --- | --- |
| 主板、创业板不再把150股买单静默取整 | 服务端拒绝不合法申报；页面禁止提交并说明100股整数倍要求；真实临时后端浏览器验收通过 |
| 科创板200股起、逐股递增 | 201股原数提交、成交、保存、刷新；199股买单不能提交；页面实际点击验收通过 |
| 最低申报数量不变成最低成交数量 | 合法委托允许按股部分成交；测试覆盖199+2股成交、主板99股零股处理、科创板止损仅余1股继续退出 |
| 数量限制与资金/T+1共存 | 比例买入按板块步长扣除费用后计算；比例卖出保留最低申报要求，全仓退出可处理零股；已有可卖与新买锁定混合时仍能处理可卖尾数；同根容量继续共享 |
| 按板块、日期识别涨跌停 | 主板普通10%，科创板20%，创业板2020-08-24前10%、之后20%；主板6%和创业板/科创板10%一价bar不误当涨停；在正确边界只限制买涨停、卖跌停方向 |
| 原始报价、复权坐标和日基准一致 | 原始前收盘参考价先按0.01元计算边界，再与原始OHLC比较；5分钟快照补充原始OHLC、复权乘数、当日前收盘参考价，不以相邻5分钟收盘价替代日基准；不改变现有复权方法 |
| 未知特殊状态不虚构成交 | 缺可靠日参考价、可检出的历史5%模糊边界、超出普通幅度或明确未知状态显示rule_unavailable，不生成成交，自动播放暂停；限价和止损保留已有生命周期 |
| 旧会话成绩保持 | 新日线/hybrid会话冻结bar-orders-v2，旧bar-orders-v1和legacy-next-open不升级；数据库重开与复练继承原版本 |
| 范围受限且Demo兼容 | 不接入北交所、B股、ETF、存托凭证；已有合成Demo、旧纯1分钟入口保持bar-orders-v1；页面只显示板块与数量约束，不暴露代码、原始日期和私有报价字段 |

单笔数量上限：主板100万股；2020-08-24后的创业板限价30万、市价15万，之前100万；科创板限价10万、市价5万。全持仓条件退出是持续意图，每次执行受对应上限、可卖数量、成交容量约束。

## 改动位置

- `backend/src/replay-board-rules.js`：集中管理板块数量、日期规则、价格边界与无法评估状态。
- `backend/src/replay-order-execution.js`：新模型按股成交、处理尾数与方向性涨跌停限制；旧模型保留原算法。
- `backend/src/db.js`、`replay-lifecycle.js`、`replay-interaction.js`：新会话版本、申报校验、匿名规则投影与状态提示，沿用同一SQLite事务。
- `engine/replay_engine/minute_replay.py`、`tdx_market_cache.py`：为新5分钟快照提供日参考价及原始坐标；保留工作区原有TDX修复，没有改写其内容。
- 现有Vue交易台与下单面板：按板块给默认股数、校验与说明，显示未知规则原因；保留原布局和组件。

架构决策见[ADR-0004](../adr/0004-ashare-board-rules.md)。

## 明确保留的边界

这仍是普通A股板块规则下的K线级教学模型。当前源缺少完整历史ST、重新上市、退市整理、特殊无涨跌幅窗口等状态，不能声称已重建全部历史制度。源中有明确涨跌停/无幅度标记时优先使用；能识别为信息不足的bar不撮合，但没有逐日权威状态表，仍不能保证识别所有历史特殊状态。不会以当前证券名称反推其历史状态。

不模拟盘口排队、连续竞价价格笼子、临时停牌与盘后撮合。挂单不预冻结资金的既有边界继续保留。本批没有扩展历史全市场、画线持久化或公司行动账本。

本阶段之后，样本维护与覆盖、同场景首次/复练对照、跨会话训练分析均已完成；当前状态见[方案总览](2026-10-19-ashare-followup.md)。
