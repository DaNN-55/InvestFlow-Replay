## 接口与资金

```js
const engine = createCryptoMarketReplay({ rules, scenario, dataVersion, slippageBps: 2 });
let state = engine.create({ startingCash: "10000", leverage: "5" });
let result = engine.apply(state, { type: "market-open", side: "long", contracts: "10" });
result = engine.apply(result.state, { type: "advance", minutes: 15 });
```

- 版本：`okx-market-minute-teaching-v1`；教学接管仍为 `isolated-full-loss-teaching-v1`。构造时显式提供固定规则、已验证内部场景和数据版本。
- `create()` 只创建纯计算初态，没有业务会话。`apply()` 返回新状态、本次增量轨迹、实际推进分钟和暂停标记；不修改输入，不获取实时时钟或随机数。
- 命令为 `market-open`、`market-close`、`add-margin`、`cancel-market`、`advance`。当前开仓要求空仓，不要求自动止损；反向须先完成平仓。平仓可给张数，省略则全部平仓；同向加仓留给 P3b。
- 提交开仓以已知普通 close＋选定滑点估算保证金与 taker 费，资金从可用转为 reserved。到下一未展示分钟才释放预留，按该分钟 open 模拟实际成交并再次检查资金；不足则拒绝、释放且不收费。市场张数上限采用冻结规格。
- P3a 对不足该分钟普通成交张数的单子整笔拒绝，不伪造部分成交。容量依据是**完整执行分钟的成交张数**，在该分钟结束才知道，属于分钟教学近似，不是已知开盘盘口或真实成交保证。轨迹带 `liquidityAssumption`；未来 P3b 扩展部分撮合。
- 逐仓 M 不因 mark 涨跌而重置。追加只做 available−x/M＋x；平仓比例释放，费用与资金费各记一次。每次转换校验 `available + reserved + M + 未实现盈亏 = 起始现金 + 普通已实现盈亏 − 普通费用 − 已收付资金费 + 接管合计 + 未实现盈亏`。
- 教学接管只有合计 `-M` 计入接管损益，实际接管成交价和官方精确 clearance 为 null；参考费、剩余权益核销和缺口豁免不再扣款。负 M 的正合计是核销桥接，不计作交易盈利。普通主动退出产生的数学现金缺口另列 `cashDeficit`，不静默使用接管豁免。

状态和轨迹是**可信内部计算材料**，包含版本信息，不可直接充当盲测 HTTP 响应。未来 P4 必须用服务端状态限定游标、冻结真实输入与版本，并由现有事务入口处理 actionId/revision、重试和恢复。纯函数的确定性不等于已经完成持久化幂等或授权。

## 分钟顺序及歧义

游标表示已完成分钟。边界资金费在进入下一次用户操作前已处理；开局为空仓，源事件恰好在开局时不对随后才开的仓位收费。

1. 用当前分钟 mark open 检查开盘缺口，必要时撤待执行单、复核、接管。
2. 在普通 open 执行待执行市价单，再用 mark open 检查新状态。已完成的开盘平仓不会被后来的极值追溯撤销。
3. 对该分钟内、边界前的资金费，保留源秒数。用事件前最近已完成分钟的 mark close 作为近似；08:00:01 不取 08:00 到 08:01 才完成的 close。
4. 若持仓且该分钟有内部资金费、mark 高低不相等，分别计算「内部资金费→不利 mark 极值」和「不利 mark 极值→内部资金费」两条教学路径，各自保留资金费的已知先后。都处理完已知收盘与结束边界资金费后，取分钟末账户权益较低者，同值优先资金费在前。记录两种结果、选择原因和真实路径未知。
5. 单纯极值触发也只标明发生于哪个分钟区间，不编造触发秒数或实际清算 fill。边界资金费在已完成价格之后处理，随后暂停或进入下分钟。

这只是在所列两条路径中取保守结果，不声称覆盖所有真实秒级排列。资金费源时间的持仓资格是训练约定；归档不能证明实盘冻结资格时刻和发布时延。ETH 本窗有秒差，两币在结束附近按原始事件时间得到不同源事件计数，不能解释为真实可套利的规则。
