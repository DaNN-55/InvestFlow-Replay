# A股首次与复练对照实现与验收

日期：2026-10-20。分支：`codex/replay-order-execution`。本批仅实现用户已确认的同场景首次与历次复练对照，附带缓存状态摘要精简和配色。未提交、推送，也未改变正式练习的订单或进度。

## 已实现与成功条件

| 可检查结果 | 对应改动与验证 |
| --- | --- |
| 同一场景的首次、第2次、第3次可并排对照 | 沿完整冻结场景指纹分组；新增只读comparison接口和共用对照抽屉，历史详情、揭晓后的复盘均可进入；多代复练与不同基准隔离有真实HTTP回归 |
| 首次原始结果保留，复练不混入首次成绩 | 读取既有attempt信息，首次固定为基准；修正不重算冻结scoreCard，不新增结果库，不回写会话；首次软删除后明确不可用，不把复练提升为首次 |
| 对照有判断、买卖时点、仓位、费用、收益与回撤 | 指标表包含原始评分、收益率、最大回撤、交易费用、平均/最高仓位、买卖成交笔数；下方并排展示原始判断、用户确认的问题、实际委托成交及原始/修正时间线 |
| 条件不同不冒充能力变化 | 费用、资金、执行规则、评分规则或结束进度不同会提示且隐藏差值；未知旧评分版本和已知新版本不能直接比较。收益或仓位差值用百分点，不自动解释为纪律提高 |
| 未揭晓结果不泄露，缺失评分不是0分 | 选中未揭晓记录返回409；组内未揭晓尝试只返回基础状态，不返回判断、交易、成绩；缺失评分显示“—”，未评分时只计算客观指标，不生成评分 |
| 缓存摘要更短且颜色准确 | 每板块显示“日线 已更新 / 5分钟 待更新 N”；省略“失败0”等冗余项，已更新绿色，待更新黄色，失败单独红色；浅色/深色均有浏览器断言 |

决策与契约见[ADR-0006](../adr/0006-replay-attempt-comparison.md)。核心代码：`backend/src/replay-comparison.js`、既有database/store/interaction边界，前端共用`ReplayAttemptComparison.vue`与`replayAttemptComparison.js`。没有把比较逻辑放入行情引擎，也没有请求TDX来生成报告。

## 验证结果

- 全部后端：154项通过，含真实HTTP的多代链、分页、不同基准、未揭晓脱敏、首次删除、费用变更和冻结评分不变。
- 全部前端单元：194项通过，新增缺失值、服务端许可差值、次数选择与部分成交展示案例。
- 全部浏览器：49项通过，含真实临时账本的两个页面入口、多代切换、嵌套抽屉关闭、缺失首次、窄屏、失败重试及缓存绿/黄配色。
- ESLint、生产构建、diff空白检查通过。
- 应用内浏览器实际点击：从第三次复练进入对照、切换第二次与第四次；首次基准保持不变，第四次未揭晓结果隐藏。

实际操作使用固定行情和临时SQLite账本（独立3126/5196服务），没有给正式练习下单或交卷。验收示例首次买入5000股、费用15.52元、收益0.43%、平均仓位50.28%；第三次空仓、推进相同一步，差值逐项可核对。这些是测试数据，不是用户真实成绩。验收后已关闭临时页面、停止服务并清理临时账本，正式5180服务重启加载新代码，用户原有练习保持原快照。最后检查发现原命令会话结束后服务会退出，本次改用本机临时后台作业托管运行，服务健康与新增接口均已复核；仍可使用项目的`./stop.sh`关闭。

## 保留边界与后续

本批比较同一冻结场景；跨会话训练分析已在后续批次实现，见[分析验收](2026-10-20-ashare-training-analytics-implementation.md)。不同结束进度或规则的结果保留展示，但不计算差值；报告不会把已知行情复练当作新的盲测，也不会从亏损、空仓或自动止损反推纪律问题。

本轮确认的A股五组改进均已实现并验收。历史全市场、逐笔公司行动账本、画线持久化继续按用户取舍暂不做。
