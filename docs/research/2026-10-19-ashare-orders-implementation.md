# A 股订单首批实现与验证

日期：2026-10-19。分支：`codex/replay-order-execution`。

后续板块规则批次也已完成，详见[板块规则实现与验收](2026-10-19-ashare-board-rules-implementation.md)。下方订单首批规则和验证数量保留为该阶段记录。

## 范围与状态

实现限价、持仓止损、主动撤单、基本部分成交及余量处理，接入现有交易台、逐笔历史、刷新恢复和自动播放。没有提交或推送。

本批不实现跨会话分析、复练对照、样本维护、北交所或完整历史交易制度。此前已确认的这些后续事项仍保留在 A 股讨论文档；不修改另一对话的加密方向记录。

现有 CONTEXT.md、TDX 引擎及对应测试的未提交改动保留，本批未改写。所有成交验证使用固定行情和临时 SQLite 账户，没有下单到用户正式账本，也没有刷新真实行情缓存。

## 已实现的可检查结果

| 确认规则 | 实现与验证结果 |
| --- | --- |
| 限价不到不成交，滑点不能突破限价 | 观察后从下一bar开始；开盘满足则用开盘参考价，否则以OHLC触价近似；买价不高于限价、卖价不低于限价 |
| 普通限价单当日有效 | 有效日从首次可撮合交易日算起；收盘保留已有成交，取消未成交余量；日线提交也至少获得下一交易日一次撮合机会 |
| 部分成交与余量续挂 | 多笔委托共享同一根K线成交容量；逐次记录成交数量、费用，余量在到期或主动撤单前继续等待 |
| 止损随持仓保护 | 买入填写止损价后创建或更新持仓保护；卖出面板也可独立设置全持仓止损；只填写收盘失效条件仍用于记录和提醒 |
| 触发后持续退出 | 触发时点和触发价格持久化；反弹、跨日和重启不清除；受T+1、停牌、一字涨跌停或容量限制时等待合法执行机会 |
| 用户主动取消 | 取消余量而不撤销已有成交；支持取消尚未触发或已触发的止损；同一买单后续部分成交不会悄悄恢复已取消的保护 |
| 不自动重新开仓 | 止损触发时取消仍待执行的买入余量，避免退出完成后旧买单又重新买入；退出过程中拒绝新增买单，需用户先取消退出 |
| 不重复成交或超卖 | 继续沿用session事务、revision和actionId；容量、可卖数量和资金校验在同一事务，重复请求不增加持仓或费用 |
| 会话结束 | 自然结束或提前交卷停止未完成委托和保护，不虚构清仓；刷新及数据库重开保留真实状态 |

同一委托同日的多次成交共享最低佣金计算；停止退出跨日后按日重新计算最低佣金，费用同步写入逐笔成交和账户累计值。

## 旧会话与数据迁移

- 新会话使用冻结的 `bar-orders-v1`；已有会话归为 `legacy-next-open`，继续按原下一开盘模型执行。
- 复练继承源会话模型，避免用新规则重新解释旧成绩；旧会话界面提示新建练习使用新订单功能。
- 原成交表保留行和ID，移除“每个订单只能一笔成交”的唯一约束；委托新增执行状态JSON。
- 新接口为 `POST /api/quant/replay/sessions/:sessionId/orders/:orderId/cancel`。新增订单字段为 `orderType`、`limitPrice` 或 `stopPrice`；缺省仍接受原市场委托形状，兼容升级前actionId重试。
- 公开会话过滤内部日期、到期序号和分日费用状态；匿名阶段不因新订单字段泄露标的身份或未来行情。

结构依据见 `docs/adr/0001-replay-bar-orders.md`。订单计算不读写数据库，由现有账户推进事务统一持久化，不新增服务或第二套账本。

## 模型边界

- 成交采用K线级教学近似：以股票成交量的股数作为共享容量硬上限，不重建盘口、价位成交量或真实排队，触价不等同于实盘保证成交。
- 未成交委托不提前冻结资金，实际成交时校验余额；多单不会使现金变负，但不能把挂单看作资金已获券商预留。
- 本批继续沿用100股取整及现有涨跌停兜底的近似；已确认的板块交易规则修正属于后续批次，不能宣称本批已完整复现各板块历史制度。
- 测试通过不等于真实上游行情质量已重新验收。本批不访问真实交易账户，未发布上线。

| 页面操作 | 实际结果 |
| --- | --- |
| 从开局页选择日内模拟、20交易日；买入选择限价10元、5000股，止损9.80元 | 待处理委托正确显示限价、数量和当日有效 |

| 后续行情开9.70元、低9.60元 | 止损触发并保持持续退出；当天因T+1尚未卖出，页面明确原因 |
