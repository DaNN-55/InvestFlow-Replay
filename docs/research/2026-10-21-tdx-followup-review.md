## 范围与依据

TDX 残留变更为两份代码、三份测试：

| 文件 | 作用与结论 |
| --- | --- |
| engine/replay_engine/tdx_api.py | 对 pytdxdata 0.3.2 返回的最新 start+count 前缀统一排序，再裁出相对最新记录的 offset/count；消除上游少量请求至少100条和多页拼接带来的契约偏差 |
| engine/replay_engine/tdx_market_cache.py | 在原默认节点前增加三个候选节点；保留原节点、异常/空数据切换、连接复用和失败冷却机制 |
| engine/tests/test_tdx_api.py | 经真实 SDK 公开接口、标准/MAC 分页器，用内存传输检验股票/指数 DAY、MIN_5、MIN_1 共264组分页边界、价格与时间；撤去修正后能检出旧问题 |
| engine/tests/test_tdx_connection_reuse.py | 保留默认新节点配置测试；新增真正经过坏响应/首页空数据后切换、优先连接复用、全失败关闭、冷却后重试和旧页空数据测试 |
| engine/tests/test_minute_replay.py | 前缀断言按 len(TDX_HOSTS) 核对，兼容默认节点从3个增加到6个 |

证据为锁定 requirements 中的 pytdxdata==0.3.2 和本机对应公开 API、路由器、标准分页器与 MAC 串行分页源码。1分钟股票请求由真实 SDK 路由到 MAC 串行通道；日线/5分钟使用标准分页通道，指数请求按 SDK 自身接口执行。本轮独立探针配置了两种内存传输通道，没有联网取行情。

日线缓存的800条分页和分钟缓存的800条分页都依赖 offset-from-latest 契约；修正不改变每条记录的时间戳或价格，不改变日线/分钟合并、复权与窗口选择规则。已冻结会话的历史快照不因此重算。
