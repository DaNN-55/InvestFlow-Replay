# ADR-0013：历史池分批准入，共用已冻结会话并独立记录行情暴露

## Status

Accepted（P6 约束已实现并验证），2026-10-21。用户授权在加密分支分批扩大 BTC/ETH USDT 永续 2024–2025 历史池，核对覆盖/缺口/准入、版本冻结、无未来泄露和首次/复练；不合并或推送。

## Decision

1. 沿用官方公开 last/mark 历史 REST 与资金费日 ZIP，按季度审计；日块可恢复，保存原始请求/原文及 SHA256。2024–2025 为目标回放区间，另取此前 90 日背景和最后一个结束分钟/资金费保护事件。不得用 Binance、现货或粗周期补缺。下载失败与源数据缺口分别记录。
2. 原 P2 样本、规则和 P1–P3b 计算保持原样。新池使用独立目录、不可变日块/批次报告与内容指纹；只有离线校验通过的 72h＋90d＋1min 场景才进入候选目录。目录最后原子发布，已发布的文件不原地改写；新批次/修订另立版本。
3. 准入验证包括源身份/响应 hash、确认字段、十进制与 OHLC/成交量、minute连续/重复/双流对齐、小时/北京时间日线官方交叉核对、资金费原始时点/率/保护与因果 mark 代理。常量 8h 只在数据实际支持的窗口审计；变化或缺失不能插值，当前执行版本无法证明适用时排除该窗口并报告。
4. 回放窗口采用预先固定的每周 72h 网格，避免按盈亏挑样本。实际可用窗口与原始日期覆盖分别统计；不展示“全量可用”替代细分证据。盲测 HTTP 只给汇总计数，不给候选日期、文件路径、完整目录或未结算资金费。
5. 新会话只从尚未暴露的候选中选择，选择后沿用 P4 全量不可变场景文档和规则/config hash。恢复/复练只读数据库原快照，不读取最新池或重新下载。池升级不重算旧成绩，缺失/损坏/不支持版本显式报错。
6. 新场景身份按合约和实际回放时间窗口稳定定义，不因规则、费用、数据修订而重新算首次。旧 P4/P5 身份保持原样；选择器读取旧冻结窗口来识别已见暴露。已删除会话仍构成见过，不能删除来重置首次。
7. BTC/ETH 共享相关时段暴露组；已使用的回放区间，以及其他会话已展示的背景/前缀或揭晓完整区间，与候选回放重叠即排除“首次”选择。创建事务内再次核对，冲突拒绝，不把并发选择都算首次。复练从历史会话显式创建，不在无未见样本时自动回退成首次。
8. 仍由同一 SQLite writer 保存账户与训练记录，不新增业务数据库。行情池是只读文件供给，新增覆盖 HTTP 沿用现有 REST。UI 仅补充实际覆盖、未见可用数、耗尽与复练提示，不暴露盲测具体日期。

## Validation

见[P6 计划与验收](../research/2026-10-21-crypto-p6-pool.md)。验证源/分钟/资金费异常被拒绝；真实各批次覆盖与排除；旧会话重启和复练不受池更新影响；未来数据/最终费率扰动不改当前前缀；跨合约、背景暴露、删除和并发不会刷首次。仅使用临时数据库，不合并/提交/推送。

## F5 交付补充（2026-10-21）

行情根目录通过 `INVESTFLOW_REPLAY_CRYPTO_DATA_ROOT` 独立配置，默认不变。离线准备只接受已冻结的 v1 根指纹，先完整校验来源和暂存副本，再发布版本，最后发布池指针；不复制账本、不覆盖同名损坏版本、不自动下载补缺。readiness 核对实际运行资产，完整 check 另外核对 raw 证据链；无数据不再报告两个小样。恢复与复练继续只用原 SQLite 快照。命令及资产获取边界见[准备指南](../crypto-data.md)。
