# ADR-0002：OKX 历史合约训练使用冻结规则与独立执行版本

## Status

Accepted（产品与规则口径），2026-10-19。用户已确认默认方案与首版教学接管，并已授权独立加密分支的 P1 纯计算实现；尚未接入业务事务、界面或完整执行。接管决定见 [ADR-0003](./0003-okx-conservative-liquidation.md)。

P1 进度更新：用户已授权在独立加密分支实现纯计算，28 项测试通过；尚未接入业务事务、界面或完整执行。详见[P1 实现报告](../research/2026-10-19-crypto-p1-implementation.md)。完整业务验收仍待后续阶段。

2026-10-20 进度：P2 小样与 P3a 市价/资金风险纯调度已实现并验证；P3a 39 项测试及真实 BTC/ETH 小样通过。完整限价/保护、业务事务与界面仍未接入。见[P3a 报告](../research/2026-10-20-crypto-p3a-execution.md)。

2026-10-20 P3b 更新：完整纯订单执行已有独立新版本，36 项测试及真实 BTC/ETH 验证通过；原 P3a 数值保持不变，尚未接业务或 UI。见[ADR-0010](./0010-okx-orders-and-protection.md)和[P3b 报告](../research/2026-10-20-crypto-p3b-orders.md)。

2026-10-20 P4 更新：已接同一 SQLite 会话/业务账本事务、幂等、恢复、冻结复练及服务端游标；新增 17 项、后端全量 267 项和真实两币对账通过。仅临时数据库验证，界面未接、正式服务未启用。此前“待 P4”为对应阶段的历史状态；当前范围见 [ADR-0011](./0011-okx-session-transactions.md)和[P4 报告](../research/2026-10-20-crypto-p4-sessions.md)。


## Decision

首期采用 OKX BTC/ETH USDT 永续、逐仓、单向，以真实历史普通价格、标记价格及资金费事件训练，合约规格、保证金档位、手续费等使用核对过的固定规则版本；不逐日期恢复全部历史制度。每会话同时保存数据、规则和执行模型版本，复练沿用首次口径，更新不重算旧记录。

选择这一方式是为了个人练习的结果可解释、可复练，也避免历史规则资料不足使训练默认混用不同日期或不同交易所的制度。代价是结果表示“该规则版本下的历史行情模拟”，不代表当时交易所的真实逐笔成交或清算。手续费基线与教学滑点明确区分；未知官方强平费用不默认为零。P0-B 已按已确认教学模型关闭，强平功能仍待实现与验收，不能声称实盘精确清算已复刻。

## Implementation boundary

实施计划建议复用现有 Node/SQLite 会话事务、幂等与恢复机制，合约计算与 A 股账户/执行规则隔离，不直接套用 100 股、T+1、股票费用或收盘价估值。现有 A 股 `legacy-next-open`、`bar-orders-v1` 的语义和旧结果保持不变；不增加第二个账户写入入口。此边界是后续实现约束，不表示本轮已经新增该模块。

## Validation

[规则参数与阶段验收](../research/2026-10-19-okx-implementation-and-acceptance.md)定义规格、费用、风险触发、资金守恒、资金费、无未来泄露、版本恢复、A 股兼容及最终强平接管的分项门槛。纯计算不能访问数据库或网络，同一冻结输入和操作应得到相同结果。
