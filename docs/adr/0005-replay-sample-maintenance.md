# ADR-0005：行情缓存维护与板块覆盖

## Status

Accepted，2026-10-19。用户授权按已确认方案实现样本维护和覆盖。

## Decision

- 行情供给、更新和质量检查仍由Python引擎负责，Node只提供已有会话的已见代码集合和最近练习上下文；不另建样本库或修改冻结会话。
- 日线储备总目标保持12只，按主板、创业板、科创板均分；5分钟总目标保持3只，每板块1只。它们是未见储备目标，不是每次固定新增数。板块缺额逐板补充，失败和无候选不能冒充补足；候选优先未尝试者，分钟候选按三板块交错，避免低质量或失败候选长期阻塞缺额。
- 日线每轮按12只一批续更全部已缓存股票，单标的失败继续其他标的；批次不再永久截取最前12只。用资源级更新时间、数据日期、失败信息表示部分完成。
- 日历基准使用已缓存的指数/交易日数据，按北京时间收盘后宽限判断最近已完成交易日，不靠工作日推算节假日。5分钟历史完整标记与更新新鲜度分开，过期完整缓存增量补充、未完整缓存继续补齐；失败保留旧缓存及错误状态。增量下载前的历史边界持久保存，分页中断后必须补回该边界，不能仅凭新写入的最大时间宣称补齐。
- 引擎进程内每60秒检查维护条件，按日期和盘前/收盘后阶段去重，失败自动重试有5分钟冷却；重复访问和轮询不产生并行重复下载。首次初始化及用户重试继续复用现有入口，程序关闭不执行后台维护。
- 状态轮询只读；Node传入完整已见集合（包括删除会话记录），引擎只返回板块聚合，统计同时说明资格口径。页面不暴露当前匿名股票身份。
- 缓存覆盖与日线基础资格复用既有质量检查；精确开局资格仍按长度、基准对齐、5分钟完整度最终确定，不把缓存总数冒充可用场景数。
- 现有离线Demo不连接TDX、不启动维护任务。旧会话和旧执行模型保持原快照。

## Validation

在临时DuckDB/SQLite和固定客户端下验证超过12只的全部续更、失败不中断与重试、按板块补充及排除已见、分钟跨交易日过期/增量/中断/恢复、同进程跨日和收盘后重触发、状态只读、匿名聚合、冻结会话不变，并验证页面显示。
